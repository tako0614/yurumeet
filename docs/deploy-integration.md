# Yurumeet GA integration fixture

The isolated integration entrypoint is `bun run deploy -- yurumeet-integration --environment=integration --phase=<phase>`. It is bound to `https://ga-meet-20261012.yurucommu.com`, resource prefix `yurumeet-ga-20261012-0938`, and the immutable `v0.2.0` Worker asset pinned in `release.lock.json` (`3b952ec6c0ee048bfd303344f8053c21c01ae8bdca780db57c908c6e171d1bd0`). It has no path to the production `yurumeet` Worker or its data.

Run one phase at a time: `preflight`, `resources`, `fresh-schema`, `activate`, then `domain`. Preflight checks the exact existing account and `yurucommu.com` zone, then paginates the D1, R2, KV, Queue, Worker, and custom-domain inventories. Worker-domain filters require the requested page and consistent `count`/`total_count`; an empty filtered response is valid with `total_count:0` and `per_page:0` or the requested page size. Any collision, denied read, or incomplete inventory stops the sequence. Public DNS results do not establish whether a record is absent: zone DNS reads are denied, and wildcard responses can return 522. The final domain phase relies on the exact Cloudflare custom-domain changeset and explicit no-overwrite flags.

`resources` copies the root OpenTofu module into the private operator directory and accepts only creation of a fresh D1 database, R2 bucket, KV namespace, delivery and DLQ Queues, and the root module's random identifier. The Worker stays disabled. State and plans stay outside Git worktrees in the operator's 0700 directory and are 0600 or stricter. Raw tool/API diagnostics stay in unique 0600 files inside its private diagnostics directory. Existing resources are never imported, adopted, replaced, or destroyed.

`fresh-schema` reads that private state's exact D1 id and calls `scripts/deploy-integration-schema.mjs`. The helper confirms a fresh database and absent target Worker, probes rollback with the identical whole-script REST `{sql}` request mode, then applies the exact published Core 4.1.14 migration set with one whole-script D1 REST `{sql}` request per migration and checks the shared `yurucommu_migrations` ledger and schema. `activate` verifies all 35 expected migration names before creating only the Worker, queue consumers, and hourly cron. Supply distinct 64-hex encryption key and session salt plus a nonblank integration password credential through ephemeral `TF_VAR_encryption_key`, `TF_VAR_session_hash_salt`, and `TF_VAR_auth_password_hash` environment variables. These credentials configure this test fixture only and do not change account or membership policy. Do not put secrets in the target file or source. OpenTofu state remains sensitive private operator material.

`domain` requires the exact activated state and no existing Worker custom domain for the hostname or target service. It requires a changeset with exactly one addition and no updates, deletions, or conflicts, repeats the domain inventory, then writes with `override_existing_origin:false` and `override_existing_dns_record:false`. It reads back the hostname, service, and zone and checks the public origin. Cloudflare creates DNS and TLS as part of a Worker custom domain. A failed or uncertain write requires authoritative readback before another invocation; Wrangler's noninteractive custom-domain path is unsuitable because its override flags permit takeover.

An `APPLIED` phase result proves the exact OpenTofu plan and private state address set only. A successful domain readback and HTTP 2xx do not prove the Worker's complete bindings or authenticated product behavior. Before describing the live fixture as qualified or GA, separately read back the exact Worker artifact and binding closure from Cloudflare and run the scoped authenticated user smoke against this origin.

Set `YURUMEET_INTEGRATION_TARGET` to an absolute, link-free 0600 JSON file under a 0700 directory outside all Git worktrees and the source Git common directory. It must contain exactly `accountId`, `zoneId`, `origin`, `prefix`, `releaseTag`, `artifactSha256`, `sourceCommit`, and `stateDir`. The target binds the exact source commit and artifact pin; `stateDir` is an existing 0700 child directory. Pass the existing Cloudflare OAuth token as ephemeral `CLOUDFLARE_API_TOKEN`; never place credentials in command arguments, logs, target files, or source.

After OpenTofu apply begins, any apply or state/mode-readback failure is reported as `POST_APPLY_INDETERMINATE`. A fresh-schema executor error is reported as `POST_SCHEMA_INDETERMINATE`; a domain error from the no-overwrite PUT through provider and public-origin readback is `POST_DOMAIN_INDETERMINATE`. Stop and inspect authoritative Cloudflare state and private OpenTofu state before another invocation. This adapter has no destroy or automatic rollback path. It does not qualify production lifecycle, production data/schema, new billing or auth grants, or public service GA.

The portable bundle's deliberate D1-safe 0003 override is validated through the owning bundle generator; this fresh native D1 lane executes the exact published Core SQL files, and validates all immutable inputs before its first probe write.

The fresh-schema executor does not split SQL or modify Core trigger bodies. It sends the pinned Core runner’s complete script in one REST `{sql}` request per migration. The identical whole-script mode must first demonstrate duplicate-key rollback on the exact fresh D1. Portable SQLite tests execute all 35 SQL files and nested triggers, but do not qualify REST atomicity or a populated database update.

Activation rechecks the complete Worker inventory before planning and immediately before apply. The Cloudflare Worker upload is a PUT, so these reads cannot atomically exclude a concurrent creator with the exact same reserved fixture name; a create-only private plan is not remote conditional-create proof. A collision is refused and any uncertain upload is reconciled without replay.
