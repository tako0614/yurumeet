# Yurumeet native federation smoke — 2026-10-05

The existing release artifact smoke exercises one Worker. The federation smoke runs two instances of the same freshly built `dist/takos-worker.js` with separate disposable D1, KV, R2 and delivery queues. `bun run check` invokes it after the artifact smoke without rebuilding between them. The fixture checks the Yurumeet discovery identity while retaining the shared `yurucommu` family-engine token.

Each instance creates an owner and session through the real mobile password API. **One API-created owner per fixture is test setup, not a Yurumeet account policy.** A follows private B, B sees and accepts the request, and both Workers' relationship data and owner-facing APIs must agree. B sends a followers-only post and a direct message to A. The smoke checks signed inbox delivery, delivery jobs, remote actor cache separation, local and remote object projections, authenticated reads, and anonymous denials. The recipient activity uses a receiver-local ID while retaining the sender's wire ID in its raw envelope.

Exact peer HTTPS origins and public DNS answers are virtualized by in-workerd routers. The routers preserve URL, Host, body, digest and signature; unrecognized outbound requests are denied. The explicit `--deny-peer-key-fetch` control blocks an unsigned peer-key request and must fail the journey. The supervisor bounds the child process, and a passing JSON record is emitted only after native runtime disposal and temporary state removal. A failed journey or cleanup emits `FAILED` JSON to stderr and exits nonzero.

This is same-product, local-native evidence for Yurumeet built bytes, including native queue delivery. It does not establish public DNS/TLS, live federation or live Queue/Cron delivery, real issuer integration, retries/redrive, existing operator-data update/restore, cross-product federation, or Core publication/adoption. Those require their own evidence. This change does not alter Core packages, pins, schema, authority, or deployment state.
